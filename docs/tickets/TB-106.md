# TB-106 — Sorting by priority returns the wrong order

- **Type:** Bug
- **Priority:** Low
- **Reporter:** QA

## Description

Choosing "Sort by priority" (`sort=priority`) lists tasks as high, low, medium. Users expect the most important tasks on top: high, medium, low.

## Steps to reproduce

1. `make seed`
2. `GET /tasks?sort=priority&per_page=50`

## Expected result

Order: high → medium → low. Within the same priority, tasks with an earlier due_date come first, and tasks without a due_date come last.

## Actual result

Order: high → low → medium.

## Acceptance criteria

- [ ] Order is high → medium → low
- [ ] Within a priority: due_date ascending, nulls last
- [ ] Pagination stays correct when sorting by priority (sorting must happen in SQL)
