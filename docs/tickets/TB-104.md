# TB-104 — Project stats show wrong completion % / HTTP 500

- **Type:** Bug
- **Priority:** High
- **Reporter:** PM

## Description

The dashboard uses `GET /projects/<id>/stats` to draw a progress bar, and has two problems:

1. The "Mobile App" project has 5 of 23 tasks done, but `completion_rate` is always `0`.
2. Opening the "Game Prototype" project (no tasks yet) shows a blank dashboard because the API returns HTTP 500.

## Steps to reproduce

1. `make seed`
2. `GET /projects/1/stats`
3. `GET /projects/3/stats`

## Expected result

- Project 1: `completion_rate` ≈ 21.7 (rounded to 1 decimal place)
- Project 3: 200 with `total: 0`, `completion_rate: 0`

## Actual result

- Project 1: `completion_rate: 0`
- Project 3: HTTP 500

## Acceptance criteria

- [ ] `completion_rate` is a percentage rounded to 1 decimal place
- [ ] A project with no tasks does not cause an error
- [ ] Tests cover both cases

## Verified reproduction

- **Commit:** `34d1f28` (branch `feature/example_taskboard`)
- **Environment:** macOS 26.6.2, Python 3.12.13, Flask 3.0.3, Werkzeug 3.1.9; existing working copy (not a fresh clone) after `make setup && make seed`, server started with `make run` (debug mode, auto-reload on)

1. `make seed && make run`
2. `curl -s localhost:5050/projects` → confirm IDs: `1` = Mobile App, `3` = Game Prototype (no tasks)
3. `curl -s localhost:5050/projects/1/stats` → `"total": 23`, `"by_status": {"done": 5, "in_progress": 4, "todo": 14}`, `"completion_rate": 0` (expected 21.7)
4. `curl -i localhost:5050/projects/3/stats` → `HTTP/1.1 500 INTERNAL SERVER ERROR`; server log ends with:

   ```text
   File "taskboard/services.py", line 54, in project_stats
     "completion_rate": done // total * 100,
   ZeroDivisionError: integer division or modulo by zero
   ```

## Investigation

| # | Hypothesis | Experiment | Result |
| --- | --- | --- | --- |
| H1 | Floor division runs before `* 100`, and there is no guard for `total == 0` | Call `services.project_stats` with stubbed counts (no DB/HTTP) | `{done: 5, total: 23}` → `0`; `{done: 23}` → `100`; `{}` → `ZeroDivisionError`. **Confirmed** |
| H2 | The running server is not executing the code being read | Print `services.__file__` and the function source; check `git status`; re-run both `curl` calls | Path and source match the repo, tree clean, same output (server not restarted; debug auto-reload was on). **Ruled out** |
| H3 | The repository returns unexpected counts | Query counts via `repository.count_tasks_by_status` and raw SQL | Project 1: `{done: 5, in_progress: 4, todo: 14}` (all `int`); project 3: `{}`. **Ruled out** |

**Root cause:** both symptoms come from one expression in `taskboard/services.py:54`, `done // total * 100`. Integer floor division of a smaller number by a larger one is always `0`, and it raises `ZeroDivisionError` when `total == 0`. Reordering to `done * 100 // total` is not enough (gives `21`, not `21.7`).


**Failing tests:** `tests/test_projects.py::test_project_stats_completion_rate_is_rounded_percentage` and `::test_project_stats_for_project_without_tasks` on branch `fix/TB-104-project-stats`.
